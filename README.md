# dsh-zhihu-scroll ｜ 刷知乎

> **一句话**：每天替你刷一轮知乎 —— 按你选的领域、来源和判断权重读回答正文，
> 挑出真正值得的，攒成一本月度文章。**不点赞、不评论、不关注、不私信**。

这是一个 [DeepSeek Harness](https://github.com/deepseek-ai) 插件。产品形状参考了
[`dsh-bili-scroll`](https://github.com/c1overzz/dsh-bili-scroll)，但**代码是重写的**：
没有内置 Python、没有 MCP、不 spawn headless dsh，抓的是知乎的读接口。

```
设置 → 刷知乎
  ├─ 日常：定时目标对话 / 每天几条 / 候选数 / 卡片墙 / 本月文章
  ├─ 偏好：领域权重 · 来源权重 · 判断权重 · 关注的人 · 额外关键词 · 人设 / 文章
  ├─ 账号：浏览器登录 → 复制 cURL → 剪贴板导入 / 手动粘贴 / 测一下
  └─ 高级：数据目录（可手动指定）/ 本月文章 / 章程 / 日志 / 诊断
```

---

## 先看四行（重要）

1. **登录走传统方式：浏览器里登录知乎，复制一条请求的 cURL，粘进设置页。**
   插件没有扫码、没有短信、没有账号密码流程；Cookie 只存本机 `auth.json`（0600），
   不回显、不上传。
2. **没有互动。** 这一版不注册任何写操作工具：不点赞、不评论、不关注、不私信。
   值班 agent 手里只有「捞候选 / 读正文 / 看评论 / 交报告」。
3. **偏好是权重，不是开关。** 领域 0–5、来源 0–5、判断口径 0–5；来源权重决定每轮候选名额，
   领域权重决定排序，判断权重决定值班编辑写「为什么值得」时的侧重点。
4. **知乎的风控会拦请求。** 插件会如实区分「没登录（401）」「风控验证页（403）」「限流（429）」，
   并在设置页给出下一步；**不会假装成功**。

---

## 它做什么

- **按来源权重捞候选**：推荐流 / 热榜 / **关注动态** / **关注的人**，按权重比例分配名额。
  - 「关注的人」会主动去翻你关注列表里最近发的回答/文章；也可以在偏好里手动填具体账号。
- **按领域权重排序**：16 个内置领域（人工智能、科技互联网、科学、商业财经、心理、历史、文化、
  职场、生活、教育、健康、游戏、影视、体育、汽车、理财），每个 0–5；命中多个领域会加权求和。
- **按判断权重筛**：信息密度 / 时效 / 实操 / 观点多元，四个 0–5 的口径交给值班编辑。
- **逐条读正文再判断**：`zhihu_item` 读回答全文、文章全文、问题的前 3 条高赞回答；
  只有摘要时会明说「只读到摘要」。
- **同问题一起看**：读回答时会顺手带出同问题下其他高赞回答；主条目下面会附一个
  **「同问题下还有」** 的小列表（最多 3 条，不占每天额度）。评论区不是重点，
  只用来确认有没有被反驳。
- **写月度文章**：一个月一个 `out/大肥鱼带你刷知乎YYYY年M月.md`，最新一天在最前，分「必读 / 值得 / 一乐」三档；
  每条含「为什么值得」+ 一句原文摘录；结构化数据写 `meta/<日期>.json`（卡片墙、计数用）。
- **定时值班**：午间 12–14、夜间 18–24，一个窗口一天只跑一次；今天挑满上限就不再跑。
- **聊天里也能用**：工具全局注册，直接说「刷一轮知乎」「看看知乎热榜」就行。

## 它不做什么

- 不点赞、不评论、不关注、不私信、不改资料；
- 不替你判断投资 / 医疗 / 法律问题（这类内容最多归到「一乐」，并注明「作者观点」）；
- 不绕过知乎的验证页 / 风控（碰上了就停手，给提示）；
- 不需要 Python、不需要 `uv`、不需要下载模型。

## 装

### 前置

- DSH **≥ 0.2.1-rc.2**（桌面版 0.2.1-rc.2 上开发和验证）；
- 一个能正常登录知乎的浏览器。

### 从本地目录装（开发版）

```bash
dsh plugin --profile desktop add <本仓库路径>
```

> 桌面版的 `dsh` 在应用包里。macOS 上是：
> 下文用 `dsh` 指代 DSH CLI。桌面版通常在 `DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh`。
> 本地目录会被 pnpm 链接进去，**别移动/删除源目录**。

### 从 tgz 装（推荐分发用）

```bash
dsh plugin --profile desktop add ./dsh-zhihu-scroll-0.3.5.tgz
```

装完**重启一次 DSH**（bundle 层要重启才组装）。然后进 **设置 → 刷知乎**。
如果你用的是 web profile，把 `desktop` 换成 `web`。

## 第一次用

### 1. 登录（账号页）

1. 浏览器打开知乎，确保已登录；
2. 按 `F12` → **Network**；
3. 刷新后找一条 **Request URL 以 `https://www.zhihu.com/` 开头**的请求（如 `www.zhihu.com/api/...`）→ 右键 → **Copy → Copy as cURL**。
   **别选** `zhihu.com`、`zhihu-web-analytics.zhihu.com`、`apm.zhihu.com` 等子域的请求，那些可能不带登录 Cookie；
4. 回到 **设置 → 刷知乎 → 账号**，点 **从剪贴板导入**；
   - 浏览器没给剪贴板权限时，展开 **手动粘贴 cURL / Cookie**，把整段粘进去 → 保存；
5. 点 **测一下**：会逐项测热榜、推荐流、关注动态、关注列表、正文接口。
   哪条没通、下一步做什么，页面上都写着。

> 为什么不用扫码 / 短信：知乎对非浏览器客户端的登录轮询风控很严（本机实测扫码状态接口
> 直接 403），短信/密码登录又需要验证码。传统 cURL 里的登录态最直接、最稳，也不需要
> 插件碰你的账号密码。

### 2. 调偏好（偏好页）

- **领域权重**：选几个你真在意的领域，5 = 非常想看，0 = 不关心；
- **来源权重**：决定每轮名额。想看熟人就把「关注动态 / 关注的人」调高；想发现新东西就调高推荐；
- **判断权重**：信息密度 / 时效 / 实操 / 观点多元，决定它挑什么、怎么解释；
- **关注的人**：留空 = 用你的关注列表；填了就只翻这些人的新内容（主页链接或 `url_token`，最多 30 个）；
- **额外关键词**：一行一个，跟领域关键词一起参与匹配；
- **人设 / 文章**：只借语气，不借事实。

保存后下一轮生效，不用重启。

### 3. 跑一轮

**手动**：在任意对话里说一句「**刷一轮知乎**」，主 agent 会用插件工具跑：

**定时**：先打开一个专门用来刷知乎的对话，在 **自动值班 → 定时投到** 里选中它，
点「测试投递」确认那个对话能回 OK，再填「精确时间点」或打开午间/夜间窗口，最后打开「每天到点自动刷」。

**精确时间点**：填 `08:30, 12:30, 21:00`（逗号/换行分隔，`HH:mm`），点「保存时间」或回车。
只想半夜一次就点 **「每天 00:00」** 预设（`24:00` 也会归一成 `00:00`）。每个点每天跑一次，
到点后 **10 分钟内**仍会补跑；留空则退回旧的午间/夜间窗口。

1. `zhihu_feed` 按来源权重捞候选；
2. 粗筛后对像样的条目调 `zhihu_item` 读正文；
3. 按判断权重挑最多「每天最多几条」，调 `zhihu_report_save` 交报告；
4. 宿主写 md / JSON、更新计数、刷新卡片墙。

1–3 分钟（取决于候选数和正文长度）。报告/卡片墙在设置页看。

定时任务只会投到你选中的那个对话，不碰你当前聊天。**DSH 必须开着、目标对话必须开着、电脑不能睡**；目标对话没开着就跳过，打开后 10 分钟内会重试。

## 设置项

| 字段 | 默认 | 含义 |
|---|---|---|
| `auto` | 关 | 总开关：到点在窗口里自动跑 |
| `noon` / `night` | 开 / 开 | 午间 12–14 / 夜间 18–24 |
| `perDay` | 3 | 每天最多挑几条；0 = 只手动 |
| `candidates` | 12 | 每轮先捞多少条候选（4–30） |
| `domains` | 见默认 | 16 个领域 → 0–5 |
| `sources` | 推荐 3 / 热榜 2 / 关注动态 4 / 关注的人 3 | 来源 → 0–5，按比例分配候选名额 |
| `quality` | 信息密度 4 / 时效 3 / 实操 3 / 观点多元 2 | 判断口径 → 0–5 |
| `followingUsers` | `[]` | 主动翻的账号（主页链接或 url_token）；空 = 用关注列表 |
| `keywords` | `[]` | 额外关键词 |
| `reportLevel` | `full` | `full` / `brief` / `off`（off 只留 JSON） |
| `persona` | `''` | 人设提示词：只借语气，不借事实 |

配置存在 `$DSH_HOME/zhihu-duty/config.json`；旧版的 `feed` / `topics` 会自动迁移成来源权重 / 关键词。

## 它是怎么跑的（架构）

```
index.js                宿主半端
  ├─ 6 只工具：zhihu_feed / zhihu_hot / zhihu_item / zhihu_comments
  │            zhihu_report_save / zhihu_status
  ├─ /api/zhihu-duty/*  设置页接口（只接受本机同源请求）
  │    status / config / auth / test / run / cancel / home / report / items / logs / diagnose
  ├─ 窗口定时器          每 60s 看一次，命中且今天没跑过就开跑
  └─ runRound()          定时只投递到用户选中的「刷知乎」对话
                          · followup 带完整 role/id，避免 0.2.6 的 422
                          · 手动 /run 仍返回 400；手动在对话里说「刷一轮知乎」
client.js               浏览器半端：设置页（settings.section），四个页签
lib/zhihu.mjs           Cookie 解析、请求、热榜/推荐/关注、正文、评论、关注列表、加权 collect
lib/domains.mjs         16 个领域 + 来源/判断目录 + 权重匹配
lib/schedule.mjs        精确时间点：HH:mm 归一化、下一次、到点/10 分钟补跑判定
lib/report.mjs          月度文章 Markdown、每日 JSON、合并、计数、卡片墙
lib/config.mjs          配置默认值/迁移/清洗/窗口
lib/state.mjs           家目录、日志、状态、凭证、章程版本账本
lib/html.mjs            知乎富文本 → 纯文本
prompts/duty.md         值班章程（用户可改；改过就保留，新版落 duty.md.new）
```

**为什么手动按钮停用、定时只投目标对话**：桌面版的 `deepseek-account` 模型通道只在**前台会话**里可用。
0.2.4 试过 `parentAgent`，0.2.5 补了父级 `agentPreset`，后台/子 agent 仍然 TRANSPORT。
0.2.6 改成往主会话 `parent.followup` 投任务，但那条消息 **没有 `role` 字段**，
DeepSeek 接口直接 422 拒绝整个对话（`messages[246]: missing field role`）。
0.3.0 的做法：定时任务只投到你在设置里选中的「刷知乎」对话，`followup` 带完整 `role`/`id`；
手动 `/run` 仍停用，手动跑就在对话里说「刷一轮知乎」。这样既不碰当前聊天，也不会再产生缺 role 的消息。

**工具边界**：主 agent 本来就有全部工具，但章程仍禁止任何互动，插件自身也不注册写操作。

## 月度文章

一个月一个 md：

```
out/大肥鱼带你刷知乎2026年10月.md
```

- 每天一个 `## 2026-10-24` 分区，**最新的一天排在最前面**；
- 同一天多次手动跑，新条目按 `addedAt` 倒序并入当天分区，**不覆盖旧条目**；
- **已经写过的旧日期区块不再重写**：只重写当天和新增日期，旧内容（包括你手改的备注）原样保留；
- 每天额度是自动调度/章程的目标，**不是手动提交的硬闸**：`zhihu_report_save` 不再按 `perDay` 拦截，超出的条目也会并入当月文章；
- 整篇每次从 `meta/<日期>.json` 重建，旧内容不丢、不重复；
- 每天的结构化数据仍在 `meta/<日期>.json`，卡片墙按天读它；
- `out/<日期>.md` 是 0.2.7 及以前的旧文件，不再生成，留着当历史。

## 去重与多样性

- **同一条内容**（url/id）不会重复进主条目；`related` 里出现过的也算见过。
- **同一个问题 30 天内**只收一次主条目；换一个回答也不收，避免「同一问题不同回答」反复占位。
- **同一天同一作者最多 1 条主条目**；近 7 天出现过的作者在候选排序里降权。
- 同一问题下的其他优质回答仍然可以放进主条目的 `related`，报告会把它们放在相邻位置。

## 候选池

- 目标候选数 = `max(candidates, 10 × perDay)`，上限 200：`perDay 10` → 100 条；
- `zhihu_feed` 支持 `page`（1–10）；没选到合适的就翻页/换来源继续捞，
  **不要为了凑数放宽标准**；
- 抓候选时就会先过滤掉近 30 天同问题、今天同作者、历史同内容。

## 数据目录

默认是 `$DSH_HOME/zhihu-duty/`（`~/.dsh/zhihu-duty/`）。可以改：

- **设置 → 刷知乎 → 高级 → 数据目录**，手动填绝对路径，或点 **选文件夹**（桌面版有系统目录选择器）；
- 点 **使用此目录** 才生效，**不用重启**；
- 换目录时会把 `config.json` / `auth.json` / 月度文章 / 缓存复制过去，**不覆盖目标目录里已有的同名文件**；
- 旧目录保留，确认没问题后自己删；
- `auth.json` 里有登录态，**别选网盘同步或公开目录**；
- 如果启动环境里设了 `DSH_ZHIHU_HOME`，目录会被它固定，设置页会禁用输入。

选择记录在 `$DSH_HOME/zhihu-duty-location.json`，重启后仍然生效。

## 数据与隐私

默认都在 `$DSH_HOME/zhihu-duty/`（可以按上面改成别的目录）：

```
config.json       设置
auth.json         知乎 Cookie（0600；接口只回显字段名，不回显值）
state.json        今天跑了几轮、各窗口跑过没有、上次错误
seen.json         最近挑过的条目（防重复）
items.json        最近候选缓存（带正文，v4 被拦时兜底）
followees.json    关注列表缓存（按天）
duty.md           值班章程（可改）
charter.sha256    章程版本账本
duty.log          运行日志（1 MB 轮转一份 .1）
out/大肥鱼带你刷知乎YYYY年M月.md     月度文章
meta/<日期>.json  日报的结构化数据
```

- 不发往任何第三方；只请求 `www.zhihu.com`；
- Cookie 不写进日志、不写进报告、不出 `/status` 接口；
- 设置页接口只接受本机同源请求（Host / Origin 都必须是 `127.0.0.1` / `localhost` / `[::1]`）。

## 常见问题

**「从剪贴板导入」没反应 / 提示没权限**
浏览器没给剪贴板权限。展开 **手动粘贴 cURL / Cookie**，把 `Copy as cURL` 的内容粘进去保存。

**「热榜接口 401 / 推荐流 401」**
Cookie 里没有有效登录态。重新登录知乎，再复制一次 cURL。`hasAuth=false` 就说明没看到 `z_c0`。

**「返回了风控验证页（403）」**
先在浏览器里正常打开知乎、通过验证，等几分钟再点「测一下」。插件不会去绕验证页；
短时间连续请求只会更容易被拦。

**「正文接口（v4）没通，但热榜/推荐通了」**
列表还能用，正文会退回摘要。文章里会标「只读到摘要」。过一会儿再试，或换一条网络。

**「关注列表（v4）没通」**
不影响推荐/热榜；在偏好里手动填「关注的人」即可。

**「现在跑一轮」/自动跑**
手动按钮仍停用：请直接在对话里说「刷一轮知乎」。定时：在自动值班里选目标对话 → 测试投递 →
打开自动开关；目标对话要开着。0.2.6 的注入消息缺 `role` 会 422，0.3.0 已修成带 `role`/`id`。

**设置页里没有「刷知乎」**
1. 确认装完**重启过** DSH；
2. 看 `duty.log` 和 DSH 日志里有没有 `zhihu-scroll` 的激活失败；
3. 确认 `package.json` 的 `engines.dsh` 满足当前版本。

## 路线图 / 已知边界

- **登录**：只做传统 cURL / Cookie 导入，不做扫码、短信、密码登录。
- **关注的人**：优先用「关注列表」接口；读不到时用关注动态兜底 / 手动填账号。
- **领域**：目前是关键词匹配 + 权重排序，不是知乎话题 ID 订阅；后续可以接话题 feed。
- **多账号**：暂不支持，一个家目录一份 Cookie。
- **手机窄屏**：设置页按桌面宽度设计（`max-width:820px`），窄屏能用但不精致。
